# LIBERO-Spatial Clean GeoVLA RLDS

This public archive contains the clean, full-point-cloud LIBERO-Spatial
fine-tuning data prepared for the GeoVLA OXE/RLDS loader. It contains all 10
Spatial tasks and all 50 official successful demonstrations per task.

## Contents

- 500 episodes and 62,153 transitions after the official OpenVLA no-op filter.
- `image`: 256 x 256 RGB, JPEG-encoded by TFDS.
- `base_pc`: 256 x 256 x 3 organized XYZ in MuJoCo world coordinates.
- `state`: end-effector XYZ + quaternion + binary gripper state.
- `action`: 7D end-effector delta action; gripper uses +1=open, -1=closed.
- English language instruction and RLDS episode flags.

The RGB and organized XYZ grids use the same 180-degree convention as the
OpenVLA LIBERO evaluation preprocessing. Observations were rendered from each
recorded official simulator state rather than generated by a second action
rollout, avoiding controller-version drift. Depth comes from the original
LIBERO/MuJoCo environment; no learned or custom depth renderer is used.

This clean reproduction archive does **not** contain polarization, synthetic
point-cloud corruption, point completion, or reconstruction targets.

## GeoVLA usage

Extract the ZIP so the data root contains:

```text
libero_spatial_state_pc_no_noop/1.1.0/
```

Then select the existing GeoVLA mixture
`libero_spatial_state_pc_no_noop` and pass the extraction directory as
`--data_root_dir`. The paper-style 3D MoE settings are `--load_depth True`,
`--depth_type dit_condition_self`, `--dit_moe True`,
`--future_action_window_size 15`, `--repeated_diffusion_steps 8`,
`--action_model_type DiT-B`, and `--proprio_type shift_ee`.

## Verification

`source_validation_report.json` records source state/action equality,
rendered-image agreement, finite point clouds, and RGB-XYZ reprojection error.
`validation_report.json` records the exhaustive NPZ-to-RLDS comparison. The
release is also checked through GeoVLA's actual RLDS loader with a 16-action
future window. The adjacent `.sha256` file verifies the downloaded ZIP.

Users remain responsible for following the upstream LIBERO asset/data terms
and citing the LIBERO and GeoVLA projects when using this derivative dataset.
